# 01 项目素材卡：把期刊的作者指南借进风格门禁

## 一句话

一个从 20 篇语料里**归纳**出来的风格门禁，天生无法要求语料里不存在的东西；
借一份**成文**的期刊图表规范，是补上这类盲区的唯一低成本来源——但借什么、借多少、借了会误伤什么，必须实测。

## 五条挖掘线各轮一遍（工序 3）

| 线 | 问什么 | 本项目的事实 | 是否成研究点 |
|---|---|---|---|
| 异常 | 哪个现象和预期不一致？ | 语料取证 45,524 字节里 error bar / ± / n= / seed / s.d. / CI **全为 0 处**；而 Nature 把「必须定义误差棒与 n」写成硬要求。**从语料归纳出来的门禁，结构上不可能包含语料里没有的条目** | 是 → §2.2「语料归纳的天花板」 |
| 取舍 | 放弃了什么？代价多少？ | 42 条只取 4 条（9.5%）；换来 1 个假阳性（`CI` 当 continuous integration 用）与 1 个漏检（P6 表注不给 n） | 是 → §2.3 筛子 + §5.2 |
| 复用 | 哪个自研件被多处复用？ | 「文本特征 → 谓词」这个算子原封不动从 G1–G12 复用到 G13/G14；`paper_figure` 的 style 字典原封不动接收新色板 | 是 → §2.4 / §2.5 |
| 失败 | 哪些尝试无效？原因？ | ① 想让 G13 逐条绑定（一处声明豁免所有误差棒 → 实测 P5 通过，同 G12 的计数式缺陷）② 想只借「不依赖版面」的条目，结果 G14 只读图注，表注漏检 | 是 → §5.1 |
| 成本 | 比常规省了什么？省多少？ | +6,811 字节（+3.525%）换来两条可机检的诚实性门禁；0 GPU hours，因为全是文本正则与 rcParams | 是 → §3 表 4 |

**预算执行结果**：一条线只出一个主研究点，实际落 4 个机制小节（2.2–2.5）+ 2 条失败（5.1 两条）+ 1 条舍弃候选（「把 Nature 的栏宽/字号也搬进来」——属版面约束，不属写作规范，明确不借，见 03 §不借清单）。

## 关键取舍记录

1. **不把字符数换算成 tokens**。第一案例的 `ev-010` 就是因为 bytes→tokens 比例未标定被 dropped；
   本案例沿用同一纪律，`measure_cost.py` 只报消息数/字符数/工具调用数，token 一栏写 null 并说明原因，
   正文引用的是**第一案例已实测的 2.04M tokens**，并标明这是跨案例引用。
2. **不把「G13/G14 全绿」当成能力证明**。P0（无任何统计内容）也全绿——门禁是前瞻性的，
   只在稿件真的报告了误差时才生效。所以本案例额外造了 P1–P7 七个探针去**逼它响**，
   并用 P2/P4 证明「补上口径就转绿」，避免把「不响」误当成「通过」。
3. **载荷报两个口径并注明不可混用**：git blob 字节（LF，+6,811）与工作区字节（CRLF，200,823）。
   第一案例混用过一次口径，本案例把它写成一条显式的口径声明（§3 末）。
4. **不虚构对照实验**。本案例没有「借了 Nature 之后稿件质量提升 X」这类数字——
   那需要盲评，而本技能自陈缺外部信号（`verification: partial`）。所以 4.3 明说
   「本案例能证明的只是门禁的判定行为，不是稿件变好了」。
