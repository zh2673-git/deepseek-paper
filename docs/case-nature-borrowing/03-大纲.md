## 3.2 有意偏离（必须申报）

| 偏离 | 原因 |
|---|---|
| 摘要报 `0 total parameters / 0 activated parameters` | G2 要求参数量成对出现，而本案例确实无参数。第一案例用同一写法（0/0）通过，本案例沿用并把「0 是真实值而非占位」写进正文，避免读者以为漏填 |
| 不报 GPU hours 成本表，只报 `0 GPU hours` | 真值为 0，编一张成本表就是虚构。G3 只要求出现成本口径，不要求非零 |
| §4.4 设「本案例不能证明什么」一节 | 骨架没有这一节，但缺了它，4.1–4.3 的读数会被误读成质量提升。宁可多一节，不可让读者误读 |

## 3.3 不借清单（写在正文 §2.3，防后人以为漏了）

Nature 42 条里**明确不借**的 38 条，按拒收理由分三类：

1. **版面约束**（B4 栏宽 89/183 mm、B1 字号 5–7 pt、B2 线宽 0.25–1 pt、C1 panel 标注格式…）：
   技术报告的版面由 `paper_render` 的 HTML/DOCX 决定，写进 Markdown 源只会塞无用元信息。
2. **不可机检的流程要求**（A3 图注 <300 词需人工判、D5 Methods 设 statistics 小节需理解章节语义）：
   门禁必须是「文本特征 / 数据字段 / 渲染参数」三者之一，否则只会变成一条永远绿的摆设。
3. **与既有风格冲突**（C1 小写无括号 panel 标注 vs DeepSeek 的 `(a)/(b)`）：
   风格一致性 > 借用规范，已注明「不借」并说明理由。
